# 動画の編集・制作

提供された素材を、依頼の意図に合わせて編集する。PV、キル集、アプリ紹介は用途の例であり、ジャンルや尺を固定しない。素材生成やrepoからの撮影は、依頼に必要な場合だけ追加する。

## 依頼を編集方針にする

- 素材、目的、必須の場面、尺・縦横比、残したい音、参考作品を確認する。依頼や素材から判断できる項目は仮定を短く伝えて進め、結果を左右する不足だけ質問する。編集技術の選択をユーザーへ丸投げしない。
- 「カッコよく」などの指定から、テンポ、強調する瞬間、文字量、色、音の方向を具体化する。参考作品がある場合は特徴を分析し、素材に合う形で応用する。
- 目立つ演出、初めて説明する技法、仕上がりを左右する効果には、**名前＋見える・聞こえる変化＋今回の目的**を1〜2文で説明する。例：「パンチイン（瞬間的な拡大）を決定的な場面に使い、視線を集めます」。通常のカットや音量調整まで列挙せず、同じ技法を繰り返し説明しない。
- 説明はチャットで行い、動画内に技術解説を入れない。説明したことを理由に承認待ちにせず、依頼の範囲で制作を続ける。「勢いを増やして」「揺れは控えめに」など感覚的な修正を受け付ける。

## 素材を確認する

1. Python、FFmpeg、ffprobeの所在と必要なフィルターを確認する。見つからない場合は既存の実行ファイルやランタイムを確認し、自動でシステム設定を変更しない。
2. `scripts/video_workflow.py inspect`で尺、解像度、フレームレート、音声の有無を調べる。元素材を保持し、制作物は指定された出力場所へ保存する。
3. `frames`で確認用のフレームを抽出し、利用可能な画像・動画閲覧手段で実際の内容を確認する。抽出成功だけを内容確認として扱わない。長尺は粗く探索し、候補の前後を細かく確認する。
4. キル判定や操作の成功などは、HUD、直前直後の動き、音、指定されたタイムスタンプを根拠に判断する。画面変化の検出や少数の静止画だけで意味を断定しない。判断できない場合は候補として示すか、該当場面を質問する。

## 構成と制作

- 素材の使う区間、順序、強調、テキスト、音の扱いを編集可能なJSONや制作スクリプトへ残す。修正時は同じ制作データを更新し、完成MP4の再編集で画質を落とさない。
- 基本のカット、定速の速度変更、中央ズーム、フェード、原音・BGM、字幕合成には同梱ヘルパーを使える。操作方法と制作データは[実行手順](references/実行手順.md)を必要に応じて読む。
- ヘルパーの機能に表現を限定しない。ロゴ・画像の合成、効果音、ビート合わせ、スピードランプ、画面揺れ、凝った文字演出などは、必要な箇所だけPythonとFFmpegで追加する。[編集と確認のポイント](references/編集と確認のポイント.md)を参照する。
- 音楽の拍位置や見せ場を確認して編集する。速度変更は原音との同期・音程を考慮する。字幕や強い演出でゲームのHUD・アプリの重要な操作を隠さない。
- 既存素材を基本とし、不足を理由に無断で有料生成・外部サービスへの素材送信・公開を行わない。新規素材が必要な場合は、その必要性と利用できる手段を説明する。

## repoからの撮影が必要な場合

提供動画があれば撮影を省略する。撮影を依頼された場合は、repoの指示と起動手順を読み、実際に使えるブラウザ操作・録画手段を確認する。用途と主要機能を調べ、デモデータで再現可能な操作を撮影して素材にする。通常の録画と、撮影しやすくするためのアプリ変更を区別し、撮影だけの依頼で本体を変更しない。実際に動作確認した範囲を紹介し、録画や起動ができない場合は必要な録画素材を具体的に伝える。

## プレビュー・検証・納品

- まず低解像度のプレビューで構成と演出を確認する。依頼が単純ならそのまま仕上げ、尺や構成が大きく不確かな場合は短い試作を提示する。プレビューを必須の承認ゲートにしない。
- 完成動画をffprobeで検査し、デコードできること、尺・解像度・音声を確認する。代表フレームとカット・速度・字幕の境界を見て、文字切れ、黒い隙間、不自然な切り替えを確認する。音声を再生できる手段があれば音量・同期・終わり方も聞く。
- 視聴できなかった項目は未確認と明示し、書き出し成功を品質確認済みとしない。素材・環境の制約で実現できない演出は説明し、同じ目的に合う代案を使う。
- 動画へのリンクまたは利用可能なプレビュー、主な演出の短い説明、修正用の制作データを渡す。技術用語を覚えなくても修正を頼めるようにする。
