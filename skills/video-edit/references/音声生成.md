# Gemini TTSによるナレーション

ナレーションが選んだ演出に役立つ場合だけ使う。ユーザー提供の音声も通常の音声素材として扱える。声を増やすために台本や動画の目的を変えない。

## 生成と確認

1. 演出案で、声の有無、雰囲気、話す速度、役割を示す。採用された方向に合わせて、元資料の意味と必須情報を守った原稿を作る。固有名詞の読みは必要に応じて読み上げ用の表記へ置き換え、画面には正式表記を使う。
2. Google AI Studioでの試聴や公式資料から利用可能なTTSモデル・声を選ぶ。実際のAPI利用と費用・再生成の上限が合意済みなら、その範囲で進める。キーがあるだけで利用の合意と扱わない。キーをチャットへ貼るよう求めない。
3. 原稿をUTF-8の`narration.txt`、口調や感情の指示を`delivery.txt`などへ保存する。表示テキストと読み上げ原稿は役割に合わせて分ける。APIへ送るのは原稿と話し方の指示であり、元動画やrepo全体は送らない。
4. 代表場面の音声を生成し、実際の尺を測る。声・BGM・効果音を合わせた短いプレビューで声質、発音、間、映像との相性を確認する。尺へ押し込むための過度な早口や機械的な速度変更は避け、原稿か画面の間を調整する。
5. 確認後、同じモデル・声・基本の話し方で残りを生成する。採用したWAVを保存して映像の修正時に再利用し、原稿や発音を変えた箇所だけ再生成する。分割生成では声や口調のつながりも確認する。

## 同梱スクリプト

`scripts/gemini_tts.py`はPython標準ライブラリから公式のInteractions REST APIを呼び、1話者のPCM WAVを保存する。SDKの導入は不要。対応するモデルを`--model`で明示する。モデルの提供状況・API仕様・料金は生成前に公式資料で確認し、モデル名や価格を恒久的な前提にしない。Generate Content API向けのモデル指定はこのスクリプトでは扱わない。

以下はSkillディレクトリから実行する例。`gemini-3.8-flash-tts`と`Kore`は現行資料の例であり、利用環境に合わせて選ぶ。

```powershell
# 通信せず設定を確認する。キーも不要。
python scripts/gemini_tts.py --text-file "制作/narration.txt" --style-file "制作/delivery.txt" --model "gemini-3.8-flash-tts" --voice "Kore" --output "制作/narration.wav" --dry-run

# API利用の合意と環境変数GEMINI_API_KEYの設定後に実行する。
python scripts/gemini_tts.py --text-file "制作/narration.txt" --style-file "制作/delivery.txt" --model "gemini-3.8-flash-tts" --voice "Kore" --output "制作/narration.wav"
```

キーは環境変数`GEMINI_API_KEY`からだけ読み、URL、出力、制作データ、公開repoへ書き込まない。`--dry-run`はローカルの入力と設定を検査するだけで、モデル・声の利用可能性や生成品質は確認しない。

1回の実行につきAPI呼び出しは1回で、自動再試行・別モデルへの切り替えはしない。既存WAVは上書きしない。APIが失敗した場合は未完成の出力を除去するが、通信のタイムアウトは生成・課金が発生していない証拠にはならない。原因と残りの予算を確認してから再実行する。回数・費用上限に達したら止め、使用可能な音声や原稿を保持して相談する。

成功時にはモデル、声、保存先、実測尺をJSONで返す。APIの応答に音声がない、未完了、WAVが不正な場合は保存しない。ファイルとして成立したことと発音・演技の品質を区別する。実APIのテストと、模擬応答によるローカルテストも区別して報告する。

生成した音声は[実行手順](実行手順.md)の`audio_tracks`へ配置できる。自動の語単位字幕タイミングや読み間違い検出は同梱していない。
