# 編集と確認のポイント

## 演出の選び方と説明

| 技法 | ユーザーへの説明例 | 編集上の判断 |
| --- | --- | --- |
| パンチイン | 「瞬間的に拡大して、命中した瞬間に視線を集めます」 | 短い区間だけ拡大する。HUDや操作対象を切らない |
| スピードランプ | 「前後は速く、決定的な瞬間はゆっくりにして強調します」 | 前後の動きを確認して速度を変える。低fps素材の強いスローは滑らかにならない |
| ビートに合わせたカット | 「BGMのリズムに合わせて場面を切り替え、勢いを出します」 | 拍位置を実際の音や波形から確認する。等間隔のカットだけで拍合わせと呼ばない |
| クロスフェード | 「前の映像が薄れながら次の映像が現れ、穏やかにつながります」 | 重なりで全体の尺が短くなる。音のつなぎ方も合わせて設計する |
| 画面揺れ | 「衝撃の瞬間に画面を少し揺らし、強さを感じさせます」 | 短く抑え、余白を確保する。操作や字幕の読み取りを妨げない |
| 色調整 | 「色と明暗をそろえ、場面が変わっても統一感を出します」 | アプリ紹介ではUIの実際の色や文字の判別を保つ |

全部の演出を使わない。見せたい内容と素材に合うものを選ぶ。PVは特徴と見せ場の構成、キル集は前後の流れと衝撃、アプリ紹介は操作と結果の分かりやすさを重視する。これらを固定テンプレートとして強制しない。

## FFmpegで追加処理するとき

- Pythonの`subprocess.run`には引数のリストを渡し、`shell=False`で実行する。長いフィルターにはフィルタースクリプトや字幕ファイルを使い、Windowsのパス・日本語・引用符をテキストへ直接埋め込む処理を減らす。
- クロスフェードでは解像度、fps、timebase、pixel formatをそろえる。重なりによる尺の変化を字幕・音声の時間軸へ反映する。
- 速度は映像の`setpts`と音声の`atempo`を対応させる。原音を残すか、見せ場の効果音として別配置するかを目的に応じて決める。
- 効果音は完成動画の時間軸へ置き、BGM・原音と混ぜた結果を確認する。音割れ防止だけで聞きやすい音量が保証されるとは扱わない。
- 字幕は安全な余白に置き、長文を読める長さにする。タイトルや機能名の誤字は元資料と照合する。
- `drawtext`のフォント自動検出が失敗する環境では、存在するフォントを`fontfile`で明示する。システム設定を変更せず、日本語の表示を抽出フレームで確認する。

## 確認する箇所

- 冒頭・末尾、各カットの直前直後、速度変化、拡大、字幕の出入り。代表フレームだけでは動きと音の同期は確認できない。
- 黒い隙間、意図しない余白、縦横比の変形、画質低下、重要なUIの切れ、字幕とHUDの重なり。
- 音の開始、原音とBGMのバランス、効果音の位置、つなぎ目、末尾の切れ方。再生確認ができない場合は未確認と伝える。
- 元素材にない成功や機能を、字幕や演出で事実のように追加していないか。

## 一次資料

必要なフィルターや環境差だけを確認し、マニュアル全体を毎回読み込まない。

- [FFmpegフィルター](https://ffmpeg.org/ffmpeg-filters.html): `setpts`、`atempo`、`scale`、`crop`、`fade`、`xfade`、`amix`、`subtitles`など。
- [ffprobe](https://ffmpeg.org/ffprobe.html): 素材と書き出し結果のストリーム・尺の確認。
- [Python subprocess](https://docs.python.org/3/library/subprocess.html): 実行とエラー処理。
- [Playwrightの録画](https://playwright.dev/docs/videos): repoからブラウザ操作を撮影する依頼で、利用可能な環境の場合だけ参照。
