# 企画と体験設計

新規企画、遊びのルールの追加・変更、バランス調整で読む。既存ゲームでは決まっている体験を基点にし、依頼に関係する部分だけ扱う。

## プレイヤーの行動から企画を具体化する

世界観やジャンルに加え、次の関係を短い文章にする。

> プレイヤーは何を目指し、何を見て判断し、何を操作し、その結果をどう受け取り、次に何を選ぶか。

操作の連続だけを遊びの核としない。探索なら発見と進路、パズルなら情報と解法、育成なら投資と成長など、そのゲームで意味を持つ判断を明らかにする。鑑賞や創作が主な遊びなら、勝敗を無理に加えず、変化や達成感を説明する。

設計を左右する項目を依頼から抽出する。

| 項目 | 決めること |
| --- | --- |
| 体験の中心 | 緊張、発見、工夫、成長、物語など、主に感じてほしいこと |
| 行動と選択 | 主な操作、選べる行動、選択が結果へ影響する仕組み |
| ルール | 行動の条件、報酬や損失、勝敗・区切り・継続の条件 |
| 情報 | 判断に必要な手掛かり、現在の状態、結果の伝え方 |
| 制約 | 対象端末、入力、遊ぶ時間、制作範囲、素材と技術の条件 |

不足するすべてを質問票にしない。企画を任された場合は体験の核を提案し、その理由と仮定を示す。明確な企画がある場合は、代替案の選択を必須にしない。

## ルールを実装・確認できる形へ落とす

- 重要な行動について、実行できる条件、成功時と失敗時の変化、連続実行の扱いを決める。
- 開始、プレイ中、結果、再開など必要な状態と遷移を整理する。ポーズ、チュートリアル、ステージ選択は今回必要なものだけ加える。
- 得点、資源、体力、ターン、時間、進行などの値は、初期値、変化の条件、上限・下限、状態をまたいで残すものを区別する。
- ランダム性を使う場合は、戦略や緊張感へ与える役割を決める。生成結果に解不能、進行不能、回避不能の状態が含まれ得るなら、保証する範囲と検証方法を選ぶ。乱数の固定だけで妥当性を保証しない。
- プレイヤーが知らない内部ルールで突然損をする場合は、必要な予告、学習方法、失敗から戻る方法を設計する。

初期の数値は仮説として扱い、根拠なく「最適」と説明しない。参考作品を使う場合は、体験を生む仕組みを分析し、固有のキャラクター、文章、素材を複製する指示へ変えない。

## 最小の試作を選ぶ

まず検証したい疑問を選び、その答えを観察できる範囲にする。例えば「障害物を避ける選択が生まれるか」を調べる試作なら、操作、障害物、当たり判定、結果、再試行をつなぐ。多数のステージや長期成長を先に作る必要はない。

試作の範囲を説明するときは、次を揃える。

- 確かめたいことと、判断材料になるプレイヤーの挙動。
- 試せる操作と、開始から結果・継続までの流れ。
- 今回含む内容と、後へ送る内容。
- 必要な仮素材と、体験の検証に不可欠なフィードバック。

試作でも、何が起きたかを判断できる表示と反応を用意する。見た目が単純でも構わないが、成功・失敗を伝えられない試作から遊びの良し悪しを結論づけない。

## バランスとコンテンツを調整する

難しさを「敵を速くする」「待ち時間を増やす」だけで作らず、情報、選択肢、操作精度、失敗の代償との関係を見直す。解法の理解と操作の難しさを区別し、想定プレイヤーに合う調整を行う。

ステージ、敵、カード、会話などを増やすときは、既存要素と異なる判断や展開をもたらすかを確かめる。内容をデータ化するかは変更頻度と既存構造で決め、一度だけ使う要素まで編集基盤へ一般化しない。

プレイ結果は[プレイテストと品質確認](プレイテストと品質確認.md)の観察方法で確認する。意図した体験が弱い場合は、仮説、観察、変更する要因を対応させ、複数の数値やルールを一度に変えて原因を追えなくしない。
