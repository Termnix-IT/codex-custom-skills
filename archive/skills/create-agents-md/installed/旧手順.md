# AGENTS.mdの作成・改善

## 目的

今後のコーディングエージェントの判断に役立つ、簡潔で正確な`AGENTS.md`を作成する。一般論ではなく、実際のリポジトリから確認できる構成、コマンド、規約、注意事項を記載する。

## 調査

- ユーザーが指定した対象を優先する。対象が不明な場合だけGitのルートやプロジェクト設定から特定し、複数候補の違いが作業範囲に影響するときのみ確認する。
- 対象に適用される既存の`AGENTS.md`を確認する。`README*`、`CONTRIBUTING*`、`docs/`、`.github/`、ツール設定、パッケージ・ビルド関連ファイルは、追加・変更する指示の根拠に必要なものだけ読む。会話内で提供済み・確認済みの内容は、変更の疑いがなければ再読しない。
- `AGENTS.md`が複数ある場合は各ファイルの適用範囲を確認し、共有規則とディレクトリ固有の規則を混在させない。
- 新規作成や構成規則の変更では、記載に必要な主要言語、フレームワーク、ランタイム、主要ディレクトリを把握する。局所的な文言修正では全体調査を行わない。
- コマンドを記載・変更する場合は、該当する定義を設定ファイルや既存文書から確認する。定義の確認のためにインストールやマイグレーションを実行しない。
- JavaScriptまたはTypeScriptでは`package.json`の`scripts`、Pythonでは`pyproject.toml`、`requirements*.txt`、`tox.ini`、`noxfile.py`、`pytest.ini`を必要に応じて確認する。モノレポではワークスペース共通の規則とパッケージ固有の例外を区別する。

## 作成原則

- リポジトリ内の既存文書で使われている言語で記述する。明確な前例がない場合はユーザーの言語を使用する。
- 指示は短く実行可能な形にし、文章より箇条書きを優先する。パスとコマンドはバッククォートで囲む。
- `AGENTS.md`というファイル名と、コード、コマンド、パス、API名などの技術的識別子は既存の表記を維持する。
- スクリプト、ディレクトリ、コマンド、ポリシーを推測で追加しない。不確実な情報が今後の判断に影響する場合は、その旨を明記する。
- READMEの長い要約、一般的なツールのチュートリアル、エージェント向けの一般論を追加しない。
- 既存の`AGENTS.md`は無条件に置き換えず、有用な指示を保持しながら、古い内容、重複、矛盾を整理する。
- 共有規則とディレクトリ固有の規則を区別し、既存の配置を優先する。別の`AGENTS.md`の新設は、依頼範囲と適用されるファイル作成規則に従う。

## 記載内容

リポジトリに関係する項目だけを選び、見出しと言語は既存文書に合わせる。

- プロジェクトの概要と主要なランタイム・フレームワーク
- インストール、開発、ビルド、テストなどの主要コマンドと、確認できた前提条件
- 主要ディレクトリの役割と責任範囲
- 命名、型、アーキテクチャ、API、データなどのリポジトリ固有の規約
- 変更内容に応じて実行すべきテストやチェック、および既知の制約
- マイグレーション、生成ファイル、シークレット、ビルド成果物などに関する固有の注意事項

## 検証

- 完成した`AGENTS.md`を読み直し、リポジトリの実態や既存の指示と矛盾していないことを確認する。
- 追加・変更したパスやコマンドの根拠を確認する。調査時の確認を再利用し、未変更の項目は不整合の兆候がある場合だけ再確認する。
- 編集内容に応じた検証を実行する。文書だけの変更で無関係なビルドやテストを一律に実行しない。安全ガードと変更に必要なテスト要件を保持し、確認できなかった事項は事実として断定しない。
